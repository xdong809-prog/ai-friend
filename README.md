# AI 好友 v4

一个跑在你自己电脑上的 AI 好友：网页能聊，也能接进 QQ（通过 NapCat）。聊天记录和记忆只存在本机 `data/` 文件夹。

这一版是按《AI好友项目·完整交接文档（优化版）》重新写的，重点放在三件事上：**说话更有逻辑、更能接上上下文、更像真人**。

---

## 一、第一次使用（3 步）

**前提**：电脑装了 Node.js 18 或更高版本（https://nodejs.org ，装 LTS 版即可）。

1. **搬旧数据（用过旧版的话）**
   双击 `导入旧项目数据.bat`，直接回车（默认旧项目在 `D:\dsh\ai-friend`）。
   它会**只读**地复制：大模型 API Key、主人 QQ、NapCat 设置、好友名字和性格、和你的聊天记录与记忆。旧项目不会被改动。

2. **关掉旧版**
   新旧版都用 8787 端口，旧版的黑窗口要先关掉（NapCat 不用关，它的上报地址不变）。

3. **启动**
   双击 `一键启动QQ好友.bat`：会先拉起 NapCat（如果还没开），再启动服务并打开网页。
   只想在网页上聊，就双击 `启动.bat`。

没用过旧版的话：直接双击 `启动.bat`，在网页「设置」里填大模型 API Key 和你的主人 QQ 号，保存即可。

## 二、接入 QQ（NapCat）

旧版已经配好 NapCat 的话什么都不用改。从零开始配：

1. 准备一个 QQ **小号**当机器人（第三方协议端有风控风险，别用大号）。
2. 打开 NapCat，扫码登录小号，进入 WebUI（通常是 `http://127.0.0.1:6099/webui`）。
3. 「网络配置」→ 新建 **HTTP 服务器**，端口 `3000`。
4. 再新建 **HTTP 客户端（上报）**，地址 `http://127.0.0.1:8787/onebot`，消息格式选 **array**。
5. Token 可以不填；填了的话两处填同一个，并在网页「设置 → QQ → NapCat 连接」里也填上。
6. 网页「设置」里填你的主人 QQ（大号），保存。用大号私聊小号试试。

网页「状态」页能看到 QQ 是否在线、收发了多少条。

## 三、这一版怎么做到「更有逻辑、更连上下文、更像人」

| 方面 | 做法 |
| --- | --- |
| 上下文不断片 | 最近的聊天**原文**完整带上；更早的部分自动压缩成**滚动摘要**，并记录压到了第几条，原文和摘要首尾相接，中间不会漏掉 |
| 记得住你 | 每隔几句话，让大模型从聊天里整理记忆：基本信息（新说法会覆盖旧的，不会出现两个名字）、你的喜好和经历、**带日期的安排**（「周五面试」会换算成具体日期，到时候它会问你结果） |
| 翻旧账 | 按关键词从很久以前的聊天里找相关片段，作为参考 |
| 接话有逻辑 | 提示词要求：先弄清这句话接的是哪件事、「那个/他」指什么；连发几条当一段话回；有问题先回答；和自己说过的话保持一致；不重复问已经回答过的事 |
| 连发合并 | QQ 上你连发的几条，等你说完了合成一段一起回，不会一条一条地抢答（详见 v4.5） |
| 看懂引用 | 你在 QQ 里「回复」某条消息时，被引用的原文会一起交给模型 |
| 时间感 | 知道现在几点、星期几；隔了几天再聊会自然地接上，而不是假装一直在聊 |
| 有情绪、有生活 | 每轮先写一句内心想法（不发出去）和心情，心情会延续；它有自己「今天在干嘛」的生活背景 |
| 不像客服 | 自动删掉「作为一个 AI」「希望对你有帮助」这类句子；去掉列表、编号、markdown；句末不加句号；长段落拆成几条短消息 |
| 打字节奏 | 先停顿「看消息」，再按字数一条条发出去 |
| 小表情 | 偶尔用 QQ 原生小黄脸；开心时不会配「吐」「大哭」，你难过时不会配「偷笑」 |
| 戳一戳 | QQ 私聊里戳它，它会回应 |
| 诚实 | 平时不提自己是 AI；但你认真问它是不是 AI，它会承认 |

### v4.5 新增：等你说完再回

真人聊天经常一句话拆成好几条发。以前它只等 2.5 秒，你打下一条稍微慢一点，它就先回了前半句。现在：

| 情况 | 它怎么做 |
| --- | --- |
| 你发完最后一条 | 等 3 秒没新消息才开始回（「设置 → QQ」可改） |
| 话像没说完：「我跟你说」「对了」「然后」、逗号结尾 | 多等一倍时间 |
| 只发了一张图（多半还要配字） | 多等一半时间 |
| QQ 上显示你「正在输入…」 | 接着等，你停下或发出来再说 |
| 它已经在想 / 正准备发，你又发了一条 | 这版不发了，把你所有的话连起来重新想（一轮最多重想 2 次，不会一直不回） |
| 你一直在发 | 从第一条算起最多等 20 秒（可改），到点就回 |

几条消息会作为一段话交给模型，并提示它先弄懂你整体想说什么，再整体回应，而不是一条条分别回。网页聊天也一样：输入框里还有字（你还在打）时会接着等。

「正在输入」靠 NapCat 上报 `input_status` 事件，NapCat 不报也没关系，其余几条照样生效。

### v4.4 新增：压缩聊天记录（自己点才会做）

聊得久了，每轮要发给模型的聊天原文越来越长：更费钱、回得更慢。网页「记忆」页新增「压缩聊天记录」，**想压缩时自己点，不点不会动**：

1. 先把还没整理的聊天全部整理进长期记忆（名字、喜好、经历、安排……大底记忆不会丢）；
2. 再把旧的聊天原文压成摘要，只留最近几条原文（默认 10 条，可以改）；
3. 可选：精炼摘要、合并重复的记忆（模型要是删得太多，会自动放弃这一步）；
4. 可选：把压缩过的旧原文打包成 `data/archive/*.jsonl.gz` 归档，聊天记录文件变小；随时可以点「恢复归档的原文」放回来。

压缩前会自动备份记忆档案（`data/profiles/main.json.bak-时间`）。卡片上能看到压缩前后「每轮发给模型的内容」有多少字。QQ 里给它发「/压缩」也行，做完会把结果发给你。

## 四、常用操作

| 看 / 改它记得的事 | 网页「记忆」页，可以增删；说「记住：我不吃香菜」「忘掉香菜」也行 |

| 开机自动运行（无窗口） | 运行 `tools\autostart-install.bat`；取消运行 `tools\autostart-remove.bat`；日志在 `data\logs\server.log` |

## 五、安全

- 服务只监听本机 `127.0.0.1`，并且会拒绝其他网站在浏览器里发来的请求，你浏览的网页读不到聊天记录、改不了设置。
- 私聊默认只理主人；陌生人私聊不回。
- `/onebot` 上报可以校验签名：NapCat 和本服务填同一个 Token 后，把「上报签名校验」设为「必须」。
- `config.json` 里有明文 API Key，**不要发给别人**；日志里的 Key 和 Token 会自动打码。
- QQ 掉线时电脑右下角会弹提醒；也可以填一个手机推送 webhook。

## 六、常见问题

**启动时提示端口被占用**：旧版或上一次的服务还开着。关掉那个窗口，或者双击 `一键关闭.bat`。

**QQ 上发消息它不回**：看网页「状态」页：QQ 是否在线、主人 QQ 是否设置。再确认 NapCat 的上报地址是 `http://127.0.0.1:8787/onebot`、格式是 array。

**回复很简单、像机器人**：多半是模型没配好，或者 Key 失效 / 余额不足。去「模型」页点「测试」。也可以换个更聪明的模型试试。

**它记错了**：到「记忆」页删掉那条，或者直接跟它说「忘掉 xxx」。

**群里 @ 它不回**：旧版默认群里只潜水，导入时保持了这个设定。去「设置 → QQ」勾选「在群里被 @ 时回复」。

## 八、给开发者

- 零第三方依赖，只用 Node 内置模块；CommonJS；Node 18+。
- 改完跑 `node tools/check.mjs`：语法检查 + 全部测试（大模型和 NapCat 都是模拟的，断网也能跑）。
- 数据格式：`data/sessions/<会话>.jsonl` 每行 `{seq, role, text, ts}`；`data/profiles/<会话>.json` 存记忆；`data/state/<会话>.json` 存心情。网页和主人的 QQ 私聊共用会话 `main`；群聊上下文只保存在内存里，不落盘。
